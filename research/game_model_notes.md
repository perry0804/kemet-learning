# Kemet 六人个人模式：真实规则状态机与 AI 合法性说明

本文件用于实现一名人类玩家加五名 AI 的完整对局。配置为六人经典个人模式、9 分胜利、红蓝白黑琥珀五色能力、神祇入场；不使用团队规则或 12 分目标。

依据：已目视检查 `research/rules.pdf` 第 3 页个人板图；已读取第 7–11、18–19 页。该 PDF 为 2024 年 Rise of the Gods 公开规则版本。能力具体效果以用户三张中文帮助卡及本工作区的能力 JSON 为准。普通同色购买限制同时保留 2021 正式规则的每昼一次规则，不能把公开 WIP 漏掉的第五条件解释为取消规则。

## 1. 最先需要修正的个人板布局

规则第 3 页的图不是“每层任选五种动作”。普通个人板有 9 个固定格：

```text
                    [独立金色 Divine Power 位置]

 第三层（上层）             [移动] [招募]
 第二层（中层）          [建造] [移动] [祈祷]
 第一层（底层）       [购买 A] [购买 B] [购买 C] [祈祷]
```

建议固定 ID：

```js
const normalSlots = [
  { id: 'f3_move',    floor: 3, action: 'move' },
  { id: 'f3_recruit', floor: 3, action: 'recruit' },
  { id: 'f2_build',   floor: 2, action: 'build' },
  { id: 'f2_move',    floor: 2, action: 'move' },
  { id: 'f2_pray',    floor: 2, action: 'pray' },
  { id: 'f1_buy_a',   floor: 1, action: 'acquire', color: null },
  { id: 'f1_buy_b',   floor: 1, action: 'acquire', color: null },
  { id: 'f1_buy_c',   floor: 1, action: 'acquire', color: null },
  { id: 'f1_pray',    floor: 1, action: 'pray' },
];
const goldSlot = { id: 'divine_power', floor: null, action: 'gold' };
```

- 金色顶尖位置在图中独立于三层普通格，不给三层平衡额外增加一层，也不当作上层普通祈祷。
- 每个普通格每昼通常只能放一个标记。上层招募和中层建造各只有一格，移动、祈祷各两格。
- 三个购买格随自家已建金字塔放颜色标记；市场有五色，不代表个人板有五个购买格。
- 零级塔没有颜色；实际建造一级时选择尚未拥有的合法颜色，并给一个购买格加对应颜色标记。
- 占敌塔可以获得另一色购买资格。自己面板没有该色标记时，可按购买规则借一个其他空购买格，包括无颜色标记的格。
- 每昼结束时，三层各至少有一个标记。放在普通格上的银色标记可计入该格所在层；独立金色位置不能补三层中的空层。
- Ouadjet 可重用已有己方普通标记的格，必须记录一天一次的使用情况，以及同一格的标记列表，不能只存一个布尔 `used`。

## 2. 建议的最小权威状态

3D 场景从规则状态派生。模型动画或拖拽坐标不能直接成为拥有权、相邻性、费用或胜负的依据。

```text
GameState
  rulesetId / version
  seed / randomState
  phase / subphase
  roundNumber
  turnOrder[6] / activePlayerId
  previousTurnOrder
  players[6]
  mapZones / landAdjacency / wallEdges / harborMetadata
  zoneOccupants
  marketTileInstances / tileDefinitionRegistry
  diDeck / diDiscard
  supplyCounters
  godRiseUnlocked                 // 曾有任意玩家达到 4 分后锁存为 true
  pendingTurnBundle
  pendingAction
  pendingBattles[] / currentBattle
  effectQueue / currentDecision
  eventLog
  winnerId | null

PlayerState
  id / seatType(human|ai) / color / cityId
  pp                             // 0..11
  permanentBattleFp / permanentDivineFp
  controlledTempleIds / controlledLevel4PyramidIds  // 可派生
  normalTokenIdsAvailable
  silverTokenOwned / silverTokenAvailable
  goldTokenAvailable
  slots[{ id, floor, action, colorToken, occupants[] }]
  colorsPurchasedThisDay
  oncePerDayUses / oncePerBattleUses
  pyramids[{ districtId, level, color }]
  normalUnitIdsInSupply
  mercenaryUnitIdsOwned
  ownedTileInstanceIds
  battleHand / battleFaceUpDiscard / battleFaceDownDiscard
  diHand                         // Diversion 单独标识，不混入公共弃牌
  veteranTokens
  creatureLocations / servantLocations
  god{ identity, acquired, location, currentLp, maxLp, strength }
```

重要的数据不变量：

- 每个实体单位、标记、能力板、神兽、仆从和牌都有唯一 ID；同名或同效果不意味着同一实体。
- 对能力另存 `artworkKey`。禁止重复持有依据同图规则，不能用能力中文名或颜色代替。剑族和矛族佣兵须区分。
- 普通士兵总数在玩家供应区与地图之间守恒；买佣兵是取得对应额外模型控制权，不复制自己的十二名普通士兵。
- 普通军团、神祇是不同类型；神祇不能混入普通单位数组。
- 临时分最好由控制权计算，并保留标记来源；不要每次进入神庙就把玩家总分永久 `+1`。
- `godRiseUnlocked` 判断的是曾达到 4 分的局面，不能把反复取得、失去同一个临时分累计四次视为达标。
- 多步行动和战斗过程中可以出现规则允许的临时状态；在规定检查点验证全局上限。
- 每个等待选择的状态包含 `decisionId`、决策者和可提交的命令类型，防止双击、过期 UI 和 AI 定时器重复执行。

## 3. 完整对局主状态机

```text
SETUP_COMMON
 -> SETUP_PLAYER_SELECTION
 -> SETUP_INITIAL_ORDER
 -> SETUP_INITIAL_TROOPS
 -> SETUP_PYRAMIDS_IN_ORDER
 -> SETUP_FREE_LEVEL1_IN_REVERSE_ORDER
 -> DAY_TURN_BEGIN
    -> VICTORY_CHECK
    -> PRE_TOKEN_WINDOW
    -> TURN_BUNDLE_COMMIT
    -> ACTION_RESOLVE
       -> EFFECTS_AND_CHOICES
       -> BATTLE_STATE_MACHINE (若触发)
       -> ACTION_END_CHECKS
       -> 下一项同回合额外行动，或 TURN_END
    -> NEXT_PLAYER_WITH_NORMAL_TOKEN
       -> DAY_TURN_BEGIN
       -> NIGHT_STEP_1 (六人普通标记全部用完)
 -> NIGHT_STEP_1 ... NIGHT_STEP_9
 -> DAY_TURN_BEGIN

任意 DAY_TURN_BEGIN 满足胜利条件 -> GAME_OVER
```

### 开局值

- 每人 7 PP、12 名普通士兵、5 个普通行动标记、8 张战斗牌、个人 Diversion、随机两张 DI。
- 两个自家城区各 5 名士兵，供应区 2 名。
- 金字塔总等级为 3；只能 1/1/1 或 2/1/0，已建塔颜色不同。
- 按正常顺序放塔，按反顺序免费选一块匹配已建塔颜色的一级板。
- 神板未购买，神模型暂不在地图。
- 从白昼开始，不先发一轮夜间收入。

### 回合和行动标记

- 六个人各用 5 个普通标记，一般一昼最多 30 次普通回合；每次只有当前玩家用一枚普通标记，然后交下一人。不是人类走五次再让 AI 走。
- 一个回合可同时放普通标记，以及当前可用的银色和／或金色标记。三项行动可以自行排序，每项完整结算后再做下一项。
- 所有本回合标记在一开始一起承诺放置，避免“先看购买结果再把刚得到的银色标记插进同回合”。
- 规则第 7 页允许选择在放标记当下暂时不能结算的行动。例如先安排建造、再安排购买；前项升塔之后后项才可买。费用与目标合法性必须在每个行动真正结算时重验。
- 前项完成后，后项仍无法完成，那个行动失去，不能退还标记、改选另一格或回滚其他玩家已经看到的效果。
- 金色标记必须对应拥有能力提供的金色行动。拥有多种金色能力不等于多枚金色标记或一次全发动。
- 免费效果产生的行动不自行消耗普通标记，也不自行添加一枚普通标记。
- 三层平衡须真实按格检查。AI 每手保留足够后续普通标记覆盖未覆盖层，是安全的规划原则；不要把这个保守规划原则当成能否依靠银色／特殊能力完成平衡的唯一规则裁判。

### 胜利检查

仅在白昼自己回合开始、放任何标记之前检查：总 FP >= 9 且不存在更高分玩家，立即获胜；并列最高也赢。

- 获得第九分的行动中不立即赢。
- 金、银额外行动之间不插入新胜利检查。
- 夜晚不即时宣布达到九分的赢家；顺序完成夜晚，按下昼新的先后顺序检查。
- 玩家普通标记用尽后，本昼不再凭银／金单独获得一个回合。

## 4. 动作的合法性和结算检查

所有动作由同一个 `validateCommand -> reduce -> resolveEffects -> invariantChecks` 管道处理；AI 和人类不能分别用一套费用或规则。

### 4.1 祈祷

- 标记必须放在两个祈祷格之一，或由有效额外能力触发。
- 基础 +2 PP，叠加明确适用于祈祷行动的能力；白一级祭司不加夜间祈祷步骤。
- 每次收入经过统一 `gainPP(amount, effectId)`，封顶 11。
- 满 PP 时仍可选择祈祷并浪费溢出收入，不能因为收益为零就把合法格删光使玩家无法平衡三层。

### 4.2 建造

- 选择自己城市的一座塔，而非任意控制的敌人金字塔；每次只升这一座。
- 目标等级 > 当前等级且 <= 4。可以连升多级。
- 将每新增级对应的价格及逐层减费先计算，再合计为单一建造付费效果，最后套适用于整体付费的调整。
- 0 -> 1 须选择本局存在、自己其他已建塔没有的颜色；放塔顶与购买颜色标记。
- 实时更新四级塔控制者和临时分，更新神祇购买条件。

### 4.3 购买能力

- 能力实例仍在公共市场；控制匹配颜色且等级足够的塔；具备合法购买格；实际结算时付得起。
- 不得已拥有相同 `artworkKey`，颜色不同也不绕过这一点。
- 普通情况下，每个白昼同色最多购买一块能力。以 `colorsPurchasedThisDay` 单独记录；不能只依赖格被占用，因为借用外色塔、金色行动、神祇等会让格与购买颜色不总是一一对应。
- 有对应颜色标记时使用对应格；控制的塔色在自己面板未标示时，才按借格规则选其他空购买格。不能仅以 WIP 的缺漏泛化成“同色格被占就任意换格重复买”。
- 双重仪式明确允许本轮已购颜色，另付 1 PP；其例外不能继承到所有金色购买。Ouadjet 重用格按实际神板效果单独实现，不泛化成任意玩家可叠标记。
- 先完成付费再把板归玩家；“购买时”效果进入队列；通常其他能力在本次 Acquire 结束后起效。
- 女祭司不能回头给购买自己的一次交易减费。起始免费拥有的女祭司则可作用于第一轮后续购买。
- 失去塔不收回已买板。市场被抢走的实例不能按原计划再次生成。
- 购买同行模型时，仅放到自家城区内已有军团，或供应区；不直接投到野外部队。

### 4.4 招募

- 基础花 X PP，从供应区取 X 名士兵，分配到自己的一至三个城区，必须受实际供应限制。
- 可以向被敌军占据的自家城区招募；完成本次招募放置后，玩家决定多个触发战斗的处理顺序，自己均是进攻方。
- 普通招募不能直接给野外军团补兵；按本地征募等能力的明确许可扩展。
- 队伍容量根据能力计算，同行单位不计为普通士兵。
- 招募动作还可包含已解锁神祇的合法重新部署，见第 8 节。不要因点击“部署神”就错误再消耗一枚额外普通标记。

### 4.5 移动

建议将路径当完整行动计划验证，状态中记录 `startZoneId`、当前军团成员、剩余普通移动、`teleportUsed`、是否已进敌城区。

- 基础普通移动次数是 1；在行动开始时计算移动加成。途中捡到加移动神兽不立刻刷新移动预算；若开始时有该神兽、只移动队伍一部分而留下神兽，仍按行动开始时的预算执行。
- 普通移动跨真实陆地相邻边。尼罗河不是一般相邻边。
- 港口移动耗一次普通移动：可从任何港口离开，目的港是贸易港口或自己城市外沙漠的军事港口，除非明确能力改变。
- 普通传送花 2 PP，从有至少一级塔的城区到方尖碑地区，不消耗普通移动。每次行动通常至多一次；可前后穿插于普通移动。
- 一次行动只移动一支行进军团，可以留兵、沿途带上自己的士兵和同行单位，不能把两支分出去的队伍分别继续完整行动。
- 必须至少移动一名普通士兵，或一个独立神祇；不能单独移动普通神兽或仆从。
- 敌方城墙：行动开始时即与要跨的城墙相邻，且一行动最多进入一个敌方城区。仅取消相邻起点限制的能力不自动取消“一敌城区”限制。
- 进入敌军地区立即结束移动并触发战斗，不能胜后继续剩余步数。
- 可以在途中暂时超军团／神兽／仆从上限，合法结束点仍须符合上限。禁止为了移动可行而任意删兵删同行模型，也不要假设未来战损一定会把非法超编行动变合法。
- 同色普通军团相遇合并，神祇不能与己方普通军团合并或留下共占一格。
- 撤空敌塔城区或神庙时及时归还临时分；最终占领按行动与战斗结算后的状态更新。

## 5. 战斗必须是有暂停点的子状态机

```text
BATTLE_START
 -> WAR_COUNCIL_START_EFFECTS
 -> SECRET_COMMIT_ATTACKER_AND_DEFENDER
 -> REVEAL_AND_PAY
 -> CONFRONTATION_EFFECTS
 -> STRENGTH_SNAPSHOT_AND_WINNER
 -> IMPENETRABLE_SHIELD_SELECTION
 -> UNBLOCKABLE_DAMAGE
 -> NORMAL_DAMAGE_MINUS_SHIELD
 -> CASUALTY_END_EFFECTS
 -> REWARDS
 -> LOSER_CHOOSES_RETREAT_OR_RECALL
 -> WINNER_CHOOSES_RETREAT_DESTINATION (如果选择撤退)
 -> WINNER_CHOOSES_STAY_OR_RECALL
 -> BATTLE_END_EFFECTS_AND_CARD_CLEANUP
 -> CONTROL_AND_LIMIT_CHECKS
 -> NEXT_PENDING_BATTLE_OR_RETURN_TO_ACTION
```

### 秘密信息

- 双方各从当前战斗手牌中提交两张不同牌：一张实际使用，一张暗弃；此外提交合法战斗 DI。
- 两方完成提交前，另一方的实际选择不能泄露给对方 UI 或 AI 策略输入。
- AI 只能看到自己的隐藏手牌和公开信息，不能直接访问人类未公开的选牌或全部 `GameState`。
- 战斗中第三人不能加入 DI。普通战斗 DI 只能在军事会议提交，不许看到揭牌后补交；赛特等明确效果有独立触发窗口。
- 黑色全力出击等军事会议开始时收入先处理，之后再判断可支付的战斗 DI；但不能提前用于支付已经发生的传送。
- 整体支付不能透支 PP。不能支付的 DI 不能生效；WIP 对误交无法支付牌的处理是无效弃置，AI 应在合法性生成时避免。
- Diversion 无实战效果，揭示后回自己的手牌，不能进普通 DI 公共弃堆。

### 战力和伤亡

- 普通军团战力 = 当前士兵数 + 战斗牌 + 适用能力 + 同行单位 + DI + 自己城区加成。
- 神祇基础战力读神板，不读生命值，也不添加虚构的“神作为一名士兵 +1”。
- 比较战力时确定胜者；平局防守赢，随后伤亡不能反转此结果。
- 每点绝对防御选择保护一名士兵；他们不被普通或真实伤害移除。随后先处理真实伤害，再处理普通伤害减普通防御；自损按负号处理。
- 全部伤亡以同一场已确认的效果数据结算；进攻方先处理损失，不意味着它死光就取消自己已经形成的反击伤害。
- 与神祇相关的伤害改扣 LP，并用失去 LP 数触发相应“失去单位”能力。不能把 LP 普遍当作当前士兵数。
- 部队消失后，同行模型返回供应；神兽不能自己继续占领。

### 奖励、撤退和召回

- 进攻胜且奖励步骤还有军团：基础 +1 永久战斗分。
- 防守胜：+1 老兵。
- 每位本奖励步骤未得任何 FP 的参战者再 +1 老兵。不能简单硬编码所有败方 1、胜方 2，而不看特殊得分。
- 败方可以撤退或召回，即使胜方死光仍要离开。败方选择是否撤退，胜方决定合法退到哪里。
- 退路是相邻空地区，不走港口连接，不进非败方自己的城区；无合法退路时普通队伍必须召回。
- 普通召回全部剩余 X 名士兵，得到 X-1 PP，同行模型回供应；不能只召回一半并留下另一半。
- 胜方普通军团可以召回或留下；已经发出的基础永久战斗分不会因随后召回收回。
- 神祇败方有路必须退，无路回供应，不算召回；神祇胜方只留下，不换钱。

### 战斗牌循环

- 实际使用牌正面弃，另一张始终暗弃；两个弃牌区在规则状态上分开。
- 每场战斗通常消耗当前手牌两张。只在手牌耗尽后收回所有自己的战斗牌，包括暗弃牌；不是每场、每夜或每人回合补满。
- 无特殊换牌时八张战斗牌对应四场战斗后回收。
- 特殊战斗牌替换必须保留被移除牌的保密性，并改变玩家的实际牌集合，不能额外变成九张。
- DI 用后公共弃置；公共牌库空时才洗 DI 弃堆。不要把战斗牌或个人 Diversion 混入。

## 6. 黑夜顺序与需要保留的玩家选择

逐步骤处理所有玩家，再进下一步骤；不能给某玩家连结九步后再结下一人。

1. **圣所献祭**：控制者可移除 2 单位换 1 永久神圣分。必须有对应可支付单位／适用神祇 LP，不允许数值变负。支付导致撤空需同步控制权。
2. **三角洲神庙**：控制者可移除 1 单位换 5 PP；它不在后面的普通神庙收入中重复领取。
3. **神庙控制**：至少控制两庙，得 1 永久神圣分；圣所不是神庙。巴斯特等能力在这里触发并遵守该步骤得分上限。
4. **崇拜**：把普通神庙 PP 收入相加，一次获得；这是每位玩家的一个整体效果。
5. **祈祷**：基础 2 PP 加玩家选择弃掉的 X 个老兵所得 X PP，合计为一个整体收入；同时处理此步骤加成。不要按每个老兵分别触发黑四神圣之力。
6. **神谕**：按当前顺位每人抽 1 DI，玩家可花每 2 老兵多抽 1；白色神谕步骤能力也在这里按实际顺序处理。牌库不足会洗弃牌后续抽。
7. **征兵**：按顺位选择 X 老兵换 X 供应区士兵，只能放在未被敌军控制的自家城区；遵守模型供应与部队限制。
8. **苏醒**：弃掉剩余老兵、收回普通及已拥有的额外行动标记，重置每昼使用记录，按规则处理超上限单位。白三神之手等苏醒时能力不要丢失。
9. **天命**：按此时的总分从低到高取得选择顺位的权利；同分按上一昼顺位。每人选择任意尚空的下一昼位置，不是低分者必定排第一，也不是简单按分数排序就结束。全部选择完成才切换新 `turnOrder`。

夜晚的控制权和总分可能在前面步骤变化，应使用当时状态；决定选顺位的分数应取步骤 9 的值。

## 7. 效果系统是完整规则的一部分

能力 JSON 中的中文文本适合展示，不能仅作为介绍文字而拥有后不生效。建议每个 `tileDefinitionId` 映射到可执行定义：

```text
passiveModifiers(context)
trigger(eventType, context) -> effects / choice
purchaseEffect
goldActionDefinition
movementPermissionOverride
costModifier(scope = perLevel | wholeEffect | acquireOnly | ...)
oncePerDay / oncePerBattle limit
```

必须留出的钩子至少包括：

- 购买完成／建造付费／招募添加／移动开始／穿墙验证／传送费用／取得神庙控制。
- 军事会议开始／正面对决结束／战力结算／伤亡结算结束／战斗奖励／败方召回／胜方召回／战斗结束。
- 夜晚九步骤的各自开始或指定子时机。
- 得到 PP、花费 PP、失去单位、得到 FP、控制权变化。

每次效果保存稳定的 `effectId`，整体加钱／付费修改按同一 ID 聚合；不要因 UI 分多次动画而多触发加钱。红、白、黑、琥珀的一些能力对触发细节敏感。

每次触发按优先级与既定顺序进入队列。同一方有多个同时触发效果且顺序影响结果时，需要真实选择；AI 可自行选顺序，但不能让人类失去这个决策。

## 8. 神祇入场的独立规则

### 初次购买条件

同时满足：

1. `god.acquired === false`。
2. 本局曾有任意玩家达到 4 FP（已锁存门槛）。
3. 自己城市内至少一座四级塔；该塔即使正被对手控制也可满足这一条。
4. 自家某四级塔颜色对应的购买格为空。
5. 当前 PP >= 4。
6. 可以选择一个没有己方普通单位的自家城区放神。

购买时占对应购买格，支付固定 4 PP（不适用购买减费），翻神板，满 LP 进入所选自家城区。如果该城区有敌军，完成入场处理后触发自己作为进攻方的战斗。

公开 PDF 的 Acquire 段落最后误写“在 Recruit 结束处理这场战斗”；结合段落语义，应在当前入场行动完成后处理，不能等玩家未来另做一次招募才打。

### 死亡后重新部署

- 已购买神、模型在供应／神板上时，在招募行动中免费部署到没有己方普通单位的自家城区，并恢复最高 LP。
- 不再支付 4 PP，但需要真实招募行动或合法招募效果；不自动每轮复活。
- 不能放在野外、不能直接加入普通军团，也不能同神兽或仆从组成队伍。
- 若放入敌占自家城区，一样产生进攻战斗。
- 一个神的模型只有一个；不能地图上已有神时再生成第二个。
- 神控制地区、移动、战斗时通过军团接口处理；保持其不是 Unit/Companion 的类型区别。

六位神的专属能力需要各自 effect handler。部署一个 7 战力通用模型而没有牌面的独特效果，不等于实现神祇模块。数值及触发以已核对的 `research/gods_verified.json` 为输入；其中记录的公开版本歧义应在实现前按明确规则版本锁定，而不是运行中随机选择。

## 9. 五名 AI 的实现边界

### 统一合法动作生成

对人类和 AI 共用：

```text
getObservation(playerId)
getLegalPlacements(playerId)
getActionPlans(playerId, placement, observation)
validateDecision(decisionId, playerId, payload)
applyDecision(...)
```

- `getObservation` 排除其他玩家的 DI、暗弃牌、尚未揭示的战斗提交；公开手牌数量、正面弃牌、能力和资源可见。
- AI 不得拥有额外 PP、自动复活、无限兵、提前看人类战斗选择或忽略城墙的私有路径。
- 决策只在状态机要求它决策时调用。AI 陷入等待也不能擅自跳过人类的撤退、召回、夜晚兑换或神谕选择。
- 每个 AI 决策先产生计划，再统一验证；不合法计划不得直接变更状态。
- AI 失败后重新生成合法计划并记录原因；不要用随机任意点击或直接加资源作为兜底。

### 每个普通回合的检查清单

1. 是否已经达到回合开始胜利条件？
2. 当前是否确实轮到该 AI，还有普通标记吗？
3. 标记格是否空且类型正确，或有合法重用例外？
4. 选后能否规划覆盖三层？保留需要的上层移动／招募机会。
5. 若组合金银行动，标记是否可用，结算次序能使后项合法？
6. 所选能力是否仍在市场、符合塔色塔级及同图／同色限制？
7. 费用按真正的阶段和整体效果计算，是否可支付？
8. 兵是否在供应里，神和同行模型是否存在且可部署？
9. 路径是否满足实际地图连接、传送与城墙条件，终点容量合法吗？
10. 行动完成后应更新哪些占领分、永久分、触发和一次性记录？

### 战斗 AI

- 仅用当前剩余战斗手牌选两张不同牌；没有牌时不能临时补任意一张。
- 根据公开对方能力及公开弃牌估计对方可能范围，不读取其实际提交。
- 区分赢战力、保兵、造成损伤的价值。进攻者要把“奖励时仍存活”计入得分估值；防守者可为保神庙或造成损伤选择牌。
- DI 支付预算包含已合法到账的战争收入，不包含猜测的未来奖励。
- 败方选退／回收之后，如果需要撤退地点，由胜方 AI 或人类另行选择。
- 根据当前状态选择合法留下／召回；神祇不能进入普通召回选项。

### 夜晚 AI

- 评估献祭是否值得、会否清空神庙或神祇 LP。
- 根据 PP 上限、后续换牌／换兵机会分配同一批老兵，不能每个步骤重复花已经用掉的老兵。
- 神谕抽取和弃牌效果需要真实处理，尤其预见、暗夜仪式。
- 选顺位时用剩余空位置列表，选完马上占位，不允许五个 AI 都选择第一。

## 10. 关键实现验收局面

这些应作为有行为意义的规则检查，不是截图是否显示五个按钮：

1. 一昼六人交替使用各五枚普通标记；中途保存重载仍保持轮次、已用格和手牌。
2. 同一个玩家不能普通连续用两次唯一招募格；Ouadjet 指定例外可执行一次，并保留两个标记占用。
3. 金银组合先升级后买板成功；顺序相反且不满足条件时，该购买行动失去，不能免费改选。
4. 不同颜色但同图的主宰／神的旨意不能重复持有；剑族与矛族佣兵作为不同画面实例处理。
5. 花 2 PP 传送只消耗一次传送，不吃普通移动；进敌军即停，打完不能继续。
6. 港口航行、敌城墙起点条件和凤凰例外使用真实地图连接。
7. 暂时路过汇合超上限可继续分散，非法终点不得靠删兵修复。
8. 进攻胜但死光不发基础战斗分；防守胜无特殊给分时共得两老兵；胜方后来召回不丢普通永久分。
9. 一场战斗消耗两张牌，第四场后收回八张；暗弃不公开，Diversion 不进入公共 DI 牌库。
10. 多庙收入与老兵换钱合并整体效果，不重复触发神圣之力。
11. 夜晚得分改变天命选择顺序；低分玩家可以主动选择后手位置；下一昼才按新顺序检查胜利。
12. 自家四级塔被占仍能满足买神条件；神可以在敌占自家城区入场进攻，固定支付四点；不能在野外召唤。
13. 神死亡进入供应，在一次合法招募中满 LP 回场；不能无限免费点“复活”。
14. 八分抢庙达到九分不立即赢；下一位抢回后跌八；并列九分且轮到自己时能赢。
15. 人类与 AI 在相同观察状态下调用同一合法命令校验；AI 不能读取另一方已密封战斗选择。
