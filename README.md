# 圣域 血与沙 3D 对战沙盘

基于《Kemet: Blood and Sand》及 Rise of the Gods 神祇入场规则制作的中文桌游练习项目。玩家控制一个势力，与五个电脑对手对局，通过可旋转的 3D 棋盘完成移动、占领、购买、招募和战斗。

当前是可玩的单人练习实现，包含部分自动选择与操作限制。规则资料、能力数量和自动对局通过，均不代表已经完整复现实体版的所有交互。具体边界见[规则覆盖与已知限制](#规则覆盖与已知限制)。

## 快速启动

需要 **Node.js 22.13.0 或更新版本**、npm，以及支持 WebGL 的现代浏览器。以下命令均在包含 `package.json` 的项目根目录执行。

首次安装依赖：

```bash
npm ci
```

仅在本机使用：

```bash
npm run dev
```

默认访问 [http://localhost:3000/](http://localhost:3000/)。实际地址与端口以终端输出为准。保持启动终端运行；需要停止时按 `Ctrl+C`。

本地对局和电脑决策不需要模型 API Key，也不需要配置数据库或对象存储。

## 局域网访问

先停止已经运行的本机服务，再使用下面的命令启动：

```bash
npm run dev -- --hostname 0.0.0.0 --port 3000
```

本机仍可访问 `http://localhost:3000/`。同一局域网内的其他设备，使用运行服务的电脑 IP，例如：

```text
http://10.88.2.178:3000/
```

`10.88.2.178` 是本项目调试时使用的地址，电脑重新联网后可能改变。优先使用终端打印的 `Network` 地址。

注意：

- `0.0.0.0` 是服务监听地址，不是发给其他设备的访问地址。
- 手机上的 `localhost` 指手机自己，不能用它访问电脑上的服务。
- 默认的 `npm run dev` 可能只监听 `localhost`／`::1`，此时其他设备不能连接。
- Vinext 使用的参数名是 **`--hostname`**。
- 局域网可访问不代表多人联机。每台设备仍然各自运行一局，一名人类玩家加五名电脑对手。

macOS 排查监听和响应：

```bash
lsof -nP -iTCP:3000 -sTCP:LISTEN
curl -I http://localhost:3000/
curl -I http://10.88.2.178:3000/
```

如果仅显示 `[::1]:3000`，按上面的局域网命令重启。如果已经监听 `*:3000`，且本机通过局域网 IP 能收到正常响应，其他设备仍连不上，再检查双方网络是否互通、访客网络隔离以及系统防火墙的入站设置。

## 开始一局

1. 选择神祇，以及主、辅金字塔的颜色。当前开局使用 `2／1／0` 等级配置。
2. 按逆序选择一块免费一级能力。五名电脑对手也会参与选择，能力不保证一直有货。
3. 轮到你时，从右侧个人面板选择一个普通行动格。
4. 移动前先点选自己的军团，再点移动格；绿色圆环表示当前可到达的目标。可在下方调整起点分兵数量和移动神谕。
5. 触发战斗时，选择一张出战牌和另一张暗弃牌，并按需投入战斗神谕。揭示后结算胜负、伤亡、奖励和去留。
6. 完成普通行动后，可使用适用的金色或银色额外行动，随后点击“结束本次回合”。
7. 黑夜选择献祭与老兵兑换，完成收益结算，再选择下一轮顺位。
8. 在自己的回合开始时，至少有 9 分且没有对手分数更高，即获胜。

拖动棋盘可旋转，滚轮可缩放，右上角提供缩放、俯视和恢复视角按钮。顶部可以暂停电脑、查看规则或开始新局；点击某个势力可查看其公开信息和已有能力。

完整说明保存在 [public/rules.md](public/rules.md)，页面内可通过“规则 → 完整文档”阅读 [HTML 版本](public/rules.html)。

## 存档和恢复

对局自动保存在当前浏览器的 `localStorage` 中：

```text
键名：kemet.table.v2
状态版本：2
```

- 使用同一浏览器、同一访问地址刷新，通常会恢复该地址下保存的对局。
- 不同浏览器、设备、域名、协议或端口的存档相互独立。
- `http://localhost:3000/`、`http://10.88.2.178:3000/` 和托管站点是不同 origin，不共享存档。
- 清理站点数据或结束某些浏览器的隐私会话，可能丢失存档。
- “撤回我的上一步”使用内存中的历史快照，最多保留 20 条；刷新后不保留撤销历史。撤回后电脑会暂停。
- 当前没有云端存档、跨设备同步、多人房间或联机协议。

## 技术栈

- React 19、TypeScript。
- Vinext、Vite，使用 App Router 风格的页面组织方式。
- Three.js、OrbitControls：棋盘、棋子、摄像机和点击拾取。
- Tailwind CSS、shadcn／Base UI：操作面板、对话框和选择控件。
- Cloudflare Workers、Wrangler、Sites 插件：构建及托管集成。

实际安装版本由 `package-lock.json` 锁定。

### 状态和操作如何流动

人类操作由 `tabletop.tsx` 转换为 `Command`，交给 `apply(game, command)`。该函数复制旧状态、校验并执行操作，返回新的 `Game`；失败时返回保留原对局状态、带 `error` 的结果。

电脑通过 `aiAction()` 产生命令，再调用相同的 `apply()`。新的状态用于更新界面和 3D 棋子，同时写入本地存档。3D 模型的位置由规则状态派生，不直接通过拖动模型修改地区所有权。

主要维护入口：

- `newGame()`：初始玩家、金字塔、军团、顺位、市场和卡组。
- `canSlot()`、`canBuy()`、`canGod()`：行动格、购买和神祇入场条件。
- `moves()`：当前军团可用的移动目标、路线和费用。
- `armyStats()`、`resolveBattle()`、`finishBattle()`：战斗数值和去留处理。
- `resolveNight()`：依步骤结算所有玩家的黑夜效果。
- `score()`、`riseAndVictory()`：分数、神祇解锁门槛与胜利检查。
- `powerValue()`、`bestAIMove()`、`chooseNormalAI()`：电脑的能力与动作评分。
- `validateGame()`：返回当前状态违反不变量的描述列表，正常时为空数组。

电脑采用本地启发式评分，结合资源、占领、战力估计和已有能力选择动作。没有调用大模型，也不需要外部推理服务。

## 数据和规则维护

当前数据包含：

- **37 个地区**：18 个城区、13 个沙漠区、5 座神庙和 1 个圣所。
- **86 条能力说明**：71 条常规能力定义对应 80 块实体板，另有 15 条三级替换候选。
- **6 位神祇**。
- **11 种随机神谕，共 33 张**，另配每位玩家一张佯动。
- **8 张标准战斗牌及 4 张特殊战斗牌**：数值定义在 `lib/game.ts` 的 `CARDS` 中。

规则引擎通过 `category === '常规'` 选择本局能力。修改 `powers.json` 的描述不会自动实现对应能力；不少效果通过能力名称匹配执行，因此改名时也要检查 `lib/game.ts` 中的分支。

新增或调整能力时，需同步检查：

1. 数据定义、费用、数量与触发时机。
2. `lib/game.ts` 中的合法性、状态变更及具体效果。
3. 人类是否需要新的选择界面，以及电脑如何作出该选择。
4. `public/rules.md`、`public/rules.html` 和页面“数字版处理”的说明。

地图的逻辑位置使用归一化坐标，底图使用照片与 `homography` 映射。修改地区中心、邻接、港口或替换照片时，需要同时检查棋子位置、可点击区域和实际移动结果。

## 规则覆盖与已知限制

已接入从开局到胜利的主要对局流程：九格个人行动板、普通与额外行动、移动和传送、占领、购买、建造、招募、战斗出牌与去留、老兵、黑夜、顺位选择、神祇入场及重新部署。

当前存在以下操作范围和差异：

- 开局界面提供 `2／1／0` 金字塔配置，尚未提供 `1／1／1` 选择。
- 本局仅使用常规能力，三级替换候选保留在资料中，没有加入当前市场。
- 移动支持起点分兵和终点合并，尚不支持同一次移动途中反复留兵、收兵。
- 预见弃牌、神圣伤痕、赛特抽牌取舍、巴卡坦转换和战利品等效果，当前由系统选择处理，没有逐项提供人工选择流程。
- “勇士参拜”当前界面每次选择额外移动或额外招募，尚未串联同一次金色行动中的两种行动。
- 神祇依据公开版资料实现；索贝克的额外伤害按进攻触发。公开资料与实物的差异记录在完整规则文档中。
- 3D 棋子使用程序生成的几何模型。棋盘是实体地图照片的透视映射贴图，不包含原版全部模型的高精度复刻。
- WebGL 初始化失败时，页面会显示可选择的地区按钮列表作为降级操作入口。
- 游戏状态和电脑逻辑都在浏览器中运行，不提供服务端权威裁决或防作弊机制。

## 排查问题

### 页面或局域网地址打不开

先看启动终端是否仍在运行、实际端口是否为 3000，再按前面的局域网章节检查监听地址。更换端口可使用：

```bash
npm run dev -- --hostname 0.0.0.0 --port 3001
```

### 换地址后看不到上一局

存档按 origin 隔离。请回到原来使用的协议、地址和端口，并使用原浏览器。当前没有自动把本机存档搬到局域网地址或托管站点的功能。

### 棋盘不显示或模型加载失败

检查浏览器是否支持 WebGL，并查看开发者工具中的控制台和网络请求。确认 `/assets/board-photo.png` 等图片能从当前服务地址加载；检查 `data/map.json` 的透视参数是否与图片匹配。

### 电脑似乎没有继续行动

先确认没有按下“暂停”，并检查是否正在等待人类出牌、黑夜分配、顺位选择，或还没有点击“结束本次回合”。这些阶段会主动等待玩家，不会由电脑代替确认。

### 构建产物预览报错

先执行 `npm run build`，确认成功后再运行 `npm run start`。检查 `dist/server/wrangler.json` 是否存在，以及终端给出的具体错误。

## 托管与素材

项目包含 Sites／Cloudflare Workers 的托管配置。`.openai/hosting.json` 已绑定现有项目；本地开发不需要重新注册站点。目前没有启用 D1 或 R2 绑定，对局存档也不写入这些服务。

`dist/` 是构建产物，不作为日常源码维护。`npm run start` 只做本地预览；正式发布通过现有 Sites 工作流完成。发布用凭据不应写入 README、源码、配置文件或 Git 远程地址。

地图和能力图来自本项目提供的桌游实物照片，神祇图片来自公开参考资料，埃及背景为生成素材。素材出处和规则依据见 [完整规则文档的来源章节](public/rules.md#sources)。本项目没有为第三方桌游素材另行授予开放许可证；对外分发时应核实相应授权。
